MudExFileDisplay

One component for pdf, images, archives, office documents, markdown, audio and more. Pick a file:

<mudex-file-display url="/sample-data/sample.pdf"
                    content-type="application/pdf"
                    show-file-name="true"></mudex-file-display>

<script>
    const display = document.getElementById('file-display');
    display.setAttribute('content-type', 'image/png');
    display.setAttribute('url', '/sample-data/logo.png');
</script>

Pass content-type whenever you know it. Without it the component falls back to the browser's native viewer instead of picking the matching MudEx viewer.

Attributes, properties and events

Simple values go in as kebab-case attributes. Everything else — objects, arrays and callbacks — is set as a camelCase property on the element.

clicked 0 times 
const button = document.getElementById('event-demo');

// attribute -> strings, numbers, booleans
button.setAttribute('icon', 'M12 2 L22 22 H2 Z');

// property -> everything else: objects, sizes, colors, callbacks
button.size = 'Large';
button.onClick = () => console.log('clicked from plain javascript');

Theme

The runtime follows the operating system by default. You can override it at any time:

MudEx.setDarkMode(true);

Good to know

  • Child content between the tags is ignored — a custom element cannot receive a Blazor RenderFragment. Components that exist only to wrap content (MudExGradientText for example) therefore render empty.
  • Generic components (MudExObjectEdit<T>, MudExSelect<T>) cannot be exposed as custom elements.
  • Custom elements are display: inline by default. Give them a display and a size in your css, otherwise they collapse.
  • The first visit downloads the .NET runtime (a few MB, compressed). After that the browser cache handles it.
  • MudEx.ready is a promise that resolves once the runtime is up, MudEx.tags lists every registered tag.
