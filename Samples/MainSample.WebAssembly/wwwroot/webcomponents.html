MudEx Web Components

This page contains no Blazor, no framework and no build step — just HTML and one script tag. Every element below is a real MudBlazor.Extensions component running as a browser custom element.

MudExFileDisplay

One component for pdf, images, archives, office documents, markdown and audio. Pick a file:

<mudex-file-display url="/sample-data/sample.pdf"
                    content-type="application/pdf"
                    file-name="sample.pdf"
                    show-file-name="true"></mudex-file-display>

<script>
    const display = document.getElementById('file-display');
    display.setAttribute('content-type', 'image/png');
    display.setAttribute('file-name', 'logo.png');
    display.setAttribute('url', '/sample-data/logo.png');
</script>

Pass content-type and file-name whenever you know them. Without the content type the component falls back to the browser's native viewer, and the toolbar menu — viewer choice, download, file info dialog — only renders once it knows a file name.

Dialogs

<mudex-dialog> takes the markup between its tags and opens it through the MudEx dialog service, so the animations, drag modes and appearance options are available from plain HTML.

This markup stood between the tags

Anything goes here — bold, italic, lists, images.

  • Dragged by its header
  • Resizable at the corner

Different animation, different position.

 
<mudex-dialog id="dialog" title="Straight from HTML"
              animation="SlideIn" drag-mode="WithoutIds" max-width="Medium">
    <h3>This markup stood between the tags</h3>
    <p>Anything goes here.</p>
</mudex-dialog>

<script>
    const dialog = document.getElementById('dialog');
    dialog.open = true;                       // and false to close it again
    dialog.onClosed = ok => console.log(ok);  // fires when it closed
</script>

Editing json

<mudex-structured-data-editor> takes json, xml or yaml as a string and builds an editor for it — that is what an object editor looks like when the type is only known at runtime. 

<mudex-structured-data-editor
    data='{"name":"MudEx","tags":["blazor","webcomponents"]}'>
</mudex-structured-data-editor>

Attributes, properties and events

Simple values go in as kebab-case attributes. Everything else — objects, arrays, sizes, colors and callbacks — is set as a camelCase property on the element.

clicked 0 times 
const button = document.getElementById('event-demo');

// attribute -> strings, numbers, booleans
button.setAttribute('icon', 'M12 2 L22 22 H2 Z');

// property -> everything else: objects, sizes, colors, callbacks
button.size = 'Large';
button.onClick = () => console.log('clicked from plain javascript');

Theme

The runtime follows the operating system by default. You can override it at any time:

MudEx.setDarkMode(true);

Good to know

  • Child content between the tags is ignored — a custom element cannot receive a Blazor RenderFragment. <mudex-dialog> is the exception: its markup is captured and rendered as raw html.
  • Custom elements are display: inline by default. Give them a display and a size in your css, otherwise they collapse.
  • style and class on a MudEx element are component parameters, not the dom ones — they land on the component's own root element. Style the custom element itself through a css selector.
  • mudex-audio-player works best inside mudex-file-display (the Audio button above) — its visualizer takes its size from the surrounding box, so standalone it needs an explicit width and height.
  • The first visit downloads the .NET runtime (a few MB, compressed). After that the browser cache handles it.
  • MudEx.ready is a promise that resolves once the runtime is up, MudEx.tags lists every registered tag.
